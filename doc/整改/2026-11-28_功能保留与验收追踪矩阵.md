# OpenAILCAP 功能保留与验收追踪矩阵

> 本文是重设计/重构期间的功能防丢失控制文件。任何模块拆分、组件替换、前端框架迁移或导航调整，都必须先更新本矩阵并经产品/架构负责人确认。
> 基线：原型 14 个模块、18 个页面及现有全部入口。目标：保留率 100%，并将演示占位补成真实功能。

## 3. 跨模块完整性

- 数据模型字段被表单引用：字段删除/改名必须提示引用并提供迁移方案。
- 表单字段被 LogicFlow/BPM 使用：类型、必填、默认值变化必须进行影响分析。
- BPM 节点调用 LogicFlow：变量映射、错误、超时、重试、幂等和补偿定义一致。
- 权限规则绑定资源/API/字段/行：发布前执行策略静态检查和运行时拒绝测试。
- AppSpec 变更触发生成器：生成物可追踪源版本、编译器版本和依赖锁。
- 发布制品与环境：制品不可变，测试/预发/生产复用同一制品，环境配置外置。
- 国际化：平台、应用界面、应用数据和消息均走 locale；时区处理使用 IANA 时区。
- 插件/设备：安装、启停、升级、回滚、卸载、权限和审计均有生命周期。

## 4. 防止功能丢失的强制检查

1. 每个页面重构前保存页面截图、入口清单、DOM 事件清单、Store 字段清单和现有测试。
2. 重构后对比路由 ID、按钮/字段/节点类型、API、快捷键、权限点和业务动作，差异必须为零或有经批准的替代映射。
3. 禁止通过删除入口、禁用按钮、隐藏字段或把真实动作改成 Toast 通过回归测试。
4. 关键动作必须具备 loading、success、failure、retry、empty、permission-denied 状态。
5. 页面导航可用不代表功能通过；必须执行对应 E2E 场景。
6. 原型数据与生产数据必须明确标识；演示模式不计为后端实现完成。
