# OpenAILCAP 详细设计—原型一致性契约

> 版本：1.0.0  
> 日期：2026-11-28  
> 状态：整改基线（不是交付完成证明）  
> 适用范围：Phase 3 架构、Phase 4 详细设计、Phase 5 交互原型

## 1. 一致性原则

本文件建立双向追踪：**设计能力 → 页面/路由/代码/状态/测试**，以及**原型操作 → AppSpec/业务规则/API/权限/审计/测试**。页面存在不代表功能实现；原型交互不代表生产实现。

唯一业务定义源为版本化 AppSpec。原型 localStorage 是演示持久化层，不得称为生产数据源。生产目标栈与原型运行栈分开记录，不能将设计目标写成当前事实。

## 3. 设计能力与 AppSpec 映射

| 设计域 | AppSpec 路径 | 当前原型入口 | 当前实现级别 |
|---|---|---|---|
| 应用元数据/版本 | meta | apps | 本地交互/演示状态 |
| 数据模型/关系 | dataModels / relations | model | 本地交互；DDL 仅预览 |
| 页面/表单 | ui / forms | form | 本地交互；未接生产运行时 |
| 逻辑图 | logic | flow | 图编辑与结构仿真 |
| BPMN | workflows | bpm | XML/图编辑与结构仿真；无真实引擎 |
| 权限 | security | perm / sec | 本地规则/展示；无生产 PDP/PEP |
| 集成/插件/设备 | integrations / extensions | ops / settings | 部分入口/规划项；生产未实现 |
| 国际化/时区 | i18n | settings | 原型语言切换；完整 locale/timezone 规则未实现 |
| 部署 | deployment | ops | 演示状态；无真实部署控制面 |

AppSpec 的 Schema 是结构契约；浏览器校验器只是子集校验器。服务端必须执行完整 JSON Schema 2020-12 校验、语义校验、权限校验和引用完整性检查。

## 4. 生产 API 契约（目标接口，非当前可调用 API）

| 领域 | 方法与路径 | 关键输入 | 关键输出/副作用 | 权限与审计 |
|---|---|---|---|---|
| AppSpec | GET /api/v1/apps/{appId}/spec | appId、tenant context | spec、version、etag | app:read / app.spec.read |
| AppSpec | PUT /api/v1/apps/{appId}/spec | If-Match、schemaVersion、spec | 新 revision、diff、validation | app:design / app.spec.updated |
| Validation | POST /api/v1/apps/{appId}/validate | revisionId、target | errors/warnings、validationRunId | app:validate / app.validation.run |
| Version | POST /api/v1/apps/{appId}/versions | revisionId、message | immutable versionId | app:version:create / app.version.created |
| Compile | POST /api/v1/apps/{appId}/compile | versionId、compilerVersion | artifactId、manifest、checks | artifact:build / artifact.compiled |
| AI task | POST /api/v1/agent/tasks | prompt、appId、context、approvalPolicy | taskId、plan、status | agent:invoke / agent.task.created |
| Approval | POST /api/v1/agent/tasks/{taskId}/approve | checkpointId、decision | resumed/denied state | agent:approve / agent.approval.decided |
| Artifact | GET /api/v1/artifacts/{artifactId} | artifactId | immutable manifest/download URL | artifact:read / artifact.read |
| Publish | POST /api/v1/artifacts/{artifactId}/promotions | targetEnvironment、approval | promotionId、deployment status | deploy:promote / artifact.promoted |

统一约束：所有 API 必须校验认证主体、tenant context、对象级权限、输入 DTO、幂等键（写操作）、并发版本（If-Match）和审计事件。错误统一使用 `{code,message,traceId,details?}`。当前原型没有上述 API 服务端实现，禁止前端假装调用成功。

## 5. 操作级双向验收规则

每个主操作登记如下追踪属性：

- `designId`：详细设计章节/需求编号；
- `routeId`：SPA 路由；
- `moduleScript`：实际模块脚本；
- `appSpecPath`：被读写的 AppSpec 路径；
- `apiContract`：目标 API 或明确标记“仅本地原型”；
- `permission`：生产权限动作；
- `auditEvent`：生产审计事件；
- `testIds`：单测/集成/E2E 编号；
- `status`：design / prototype / production / verified / independently-reviewed。

缺任一必要字段的功能不能标记为已验收。新增、删除、重命名操作必须同步修改详细设计、原型、此映射和自动化测试。

## 6. 视觉与交互一致性规则

- 全站使用 `workbench-redesign.css` 的 token；页面不得私自重定义基础色、间距、圆角和阴影。
- 统一页面头部、主要操作区、内容卡片、表格、编辑器工具栏、属性面板、空/错/加载/无权限状态。
- 所有写操作提供确认/处理中/成功/失败/重试反馈；不得仅 toast 伪装后端提交。
- 保留 18 个路由与全部原有功能入口；窄屏时允许横向滚动设计画布，但不能隐藏业务入口。
- AI 面板必须显示 LOCAL DEMO，直到真实模型与 Agent 后端完成并通过端到端验证。
- 键盘焦点、语义标签、对比度、减少动态效果和窄屏布局纳入 E2E/人工验收。

## 7. 状态定义

| 状态 | 含义 | 可否计入交付 |
|---|---|---|
| D0 未设计 | 无可审查设计 | 否 |
| D1 设计完成 | 业务/数据/API/权限/异常/验收定义完整 | 仅设计进度 |
| P1 原型交互 | 浏览器可交互，数据仅本地或模拟 | 仅原型进度 |
| I1 生产实现 | 后端/运行时/安全机制真实实现 | 尚不能单独验收 |
| V1 自动验证 | 自动化测试和证据通过 | 可进入独立复核 |
| S1 独立复核 | 由独立评审确认条款/功能证据 | 可计入最终交付 |

## 8. 当前差距与禁止性声明

- 当前原型是原生 JS + localStorage，不是 React/NestJS/PostgreSQL 产品实现。
- 当前 AppSpec 浏览器校验器不是完整 Schema validator，也不是生产唯一事实源的服务端落地。
- LogicFlow/BPMN 仅编辑与结构仿真，不是生产执行引擎。
- 真实 LLM/Agent、租户 RLS、KMS/HSM、插件沙箱、设备接入、应用市场、跨平台和跨语言能力尚未由本原型实现。
- 目前 CI 静态测试不等于浏览器 E2E；L3 目标不等于已达到 L3。

## 9. 变更同步检查

修改设计或原型的 PR 必须同时通过：

1. 页面路由/入口清单检查；
2. AppSpec schema 与校验器兼容性检查；
3. 设计章节/API/权限/审计/测试映射检查；
4. 原有功能保留差异检查；
5. 浏览器 E2E（覆盖受影响页面）；
6. README、Phase 3/4/5 和本契约的状态口径一致检查。
