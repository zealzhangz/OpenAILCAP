> 版本：1.0.0 | 日期：2026-11-28
> 适用范围：原型全部 14 个模块、18 个页面、全局 AI 助手、全局搜索、表单/逻辑/BPM/ER/报表等设计器。
> 本规范约束视觉与交互，不得成为删减功能或弱化交互的理由。

## 2. 产品设计定位

OpenAILCAP 是面向企业开发者、业务分析师、平台管理员和生态开发者的 AI 原生低代码工程工作台。核心工作是：在统一 AppSpec 上，通过 AI 对话与传统设计器协作，完成建模、界面、逻辑、流程、权限、测试、发布和运维。

视觉方向：**工业级开发工作台（Engineering Workbench）**。表达精确、可读、稳定和可追踪；拒绝营销型 SaaS 首页、过度圆角卡片墙、紫色渐变、无意义装饰图标和泛化 AI 科技风。

### 2.1 视觉记忆点

唯一主记忆点放在“AI 与工程画布共享同一上下文”的工作台体验：
- 全局左侧是稳定的产品导航；
- 顶栏呈现当前应用、环境、搜索、消息、语言、主题和用户上下文；
- 内容区采用任务导向的工作区，而非一屏堆满 KPI 卡片；
- AI 面板作为可收起的协作侧栏，展示计划、工具调用、差异预览、审批与验证结果；
- 复杂设计器采用三栏/四栏专业 IDE 布局，工具栏、画布、属性和资源区职责明确。

## 3. 设计 Token

### 3.1 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `--oac-ink` | `#1D2B34` | 主文本、图标 |
| `--oac-sidebar` | `#172D3A` | 导航背景 |
| `--oac-canvas` | `#F3F6F7` | 页面工作区背景 |
| `--oac-paper` | `#FFFFFF` | 编辑面板、弹窗 |
| `--oac-teal` | `#176B78` | 主品牌、主操作 |
| `--oac-copper` | `#C66A43` | 少量强调、重要提示 |
| `--oac-line` | `#D9E2E6` | 分割线、边框 |
| `--oac-muted` | `#647681` | 次级文字 |
| `--oac-success` | `#28765F` | 成功/通过 |
| `--oac-warning` | `#A96720` | 警告/待处理 |
| `--oac-danger` | `#B44747` | 错误/危险操作 |

颜色语义必须一致；不得仅用颜色传达状态，必须同时提供文字/图标/可访问标签。图表使用色盲友好且可区分的序列色。

### 3.2 字体与层级

- 中文界面优先使用系统可用的中文无衬线字体；西文采用系统 UI 字体栈，代码/标识符使用等宽字体。
- 不强制外部字体 CDN；离线部署时不依赖公网字体。
- 页面标题 22–26px；模块标题 16–20px；正文 13–14px；辅助信息 12px；代码 12–13px。
- 正文行高 1.55–1.7；表格密度支持舒适/紧凑两档。
- 禁止无语义的全大写标签和过度字距。

### 3.3 间距、边框与阴影

- 基础间距 4px；主要间距序列 4/8/12/16/20/24/32。
- 导航宽度桌面端 248px；顶栏 56px；内容最大宽度不强制居中，按工作任务充分利用横向空间。
- 普通控件圆角 6px；弹窗 10px；画布节点/表格以清晰边界为主。
- 阴影只用于浮层和层级分离；不为每个卡片添加重阴影。
- 分割线、留白和对齐负责信息层级，不堆叠徽章和装饰。

## 4. 信息架构与页面布局

### 4.1 全局 Shell

- 左侧导航：产品标识、开发中心/运行中心/治理中心分组、模块导航、当前项状态、折叠/滚动。
- 顶栏：面包屑、当前应用与环境、全局搜索、语言、消息、主题、用户菜单。
- 主内容：页面标题/说明/主要操作区；工作区；必要的状态/审计侧栏。
- 全局 AI：可收起侧栏，显示上下文应用、会话历史、任务计划、执行步骤、工具输入输出、差异预览、确认/拒绝、恢复/重试。
- 全局搜索：覆盖应用、数据模型、表单、流程、实例、人员、插件、文档；支持键盘导航。

### 4.2 页面模板

| 页面类型 | 布局模板 | 核心交互 |
|---|---|---|
| 工作台/列表 | 标题+主要操作、筛选工具栏、数据表格、详情抽屉 | 搜索、筛选、排序、分页、批量操作、空/错/加载状态 |
| 详情/治理 | 左侧目录或对象导航 + 主内容 + 右侧属性/审计 | 版本切换、权限反查、差异、审批 |
| ER/流程画布 | 左工具栏 + 中央无限画布 + 右属性面板 + 底部诊断/日志 | 拖拽、连线、缩放、撤销重做、快捷键、校验、执行 |
| 表单设计器 | 组件库 + 画布 + 属性面板；顶栏预览/设备/保存 | 拖放、排序、校验、事件、主题、多语言、响应式预览 |
| BPM 设计器 | BPMN 工具箱 + 泳道画布 + 节点属性/参与者规则 | 标准 BPMN 导入导出、校验、仿真、版本、发布 |
| 报表/大屏 | 数据源/字段 + 画布 + 图表属性 + 预览 | 查询、筛选、下钻、刷新、导出、模板 |
| 运维/安全 | 状态概览 + 过滤器 + 事件/日志表 + 详情 | 查询、告警确认、部署/回滚、审计导出 |

### 4.3 页面全量覆盖

必须逐页应用本设计系统：工作台、应用管理、组织架构、数据建模、表单设计、逻辑编排、BPM 流程、任务待办、流程实例、报表设计、数据大屏、基础配置、权限管理、数据管理、代码开发、安全合规、运维部署、消息中心。不可只重做工作台或应用列表。

## 5. 组件与交互规范

- 按钮：主操作一个；次操作描边；危险操作红色且二次确认；按钮文字描述结果（保存、发布、回滚）。
- 表格：固定表头、行 hover、排序/筛选/分页、批量选择、空状态、加载骨架、错误重试；行操作不隐藏关键能力。
- 表单：必填/错误/帮助/禁用/只读状态完整；校验消息定位到字段；键盘可达。
- 标签：只用于状态/分类；不能用标签替代真实状态。
- 抽屉/弹窗：长流程优先页面/抽屉；破坏性动作明确影响范围。
- 画布：节点类型、端口、边、选中/校验错误/禁用/运行态有清晰区分；缩放、平移、框选、对齐、撤销/重做；操作有键盘替代方式。
- Toast 只用于动作完成后的轻量反馈，不得代替保存、发布、审批、部署等业务操作。
- AI：显示模型/任务状态、工具调用过程、置信度或不确定性、将修改的对象、权限边界；高风险动作必须人工确认。
- 数据：真实数据与演示数据明确区分；所有示例 KPI 标注“演示数据”，禁止随机变化制造实时感。

## 6. 响应式与无障碍

- 桌面优先，适配 1440/1280/1024/768/390px 宽度；设计器在窄屏提供面板折叠和可滚动工作区。
- 所有交互控件有可见 focus-visible；键盘可完成导航、表单、弹窗和主要画布操作。
- 对比度达到 WCAG 2.1 AA 目标；状态不只依赖颜色；图标按钮有 accessible name。
- 尊重 prefers-reduced-motion；非用户触发动画克制。
- 触控目标在移动端尽量不小于 40×40px。

## 7. 视觉验收清单

- [ ] 18 个页面全部使用统一 token，无页面残留旧紫色主品牌/随机渐变。
- [ ] 导航、顶栏、页面标题、主操作、内容区和 AI 面板层级一致。
- [ ] 所有 14 模块功能入口完整；重设计前后功能清单差异为 0。
- [ ] 表单、画布、表格、弹窗、抽屉、Toast、空状态、加载态、错误态统一。
- [ ] 1440/1280/1024/768/390px 视口无关键内容溢出/遮挡。
- [ ] 键盘焦点、颜色对比、减少动画、图标可访问名称通过检查。
- [ ] 每页有桌面和窄屏截图；视觉评审问题有记录和修复 commit。
- [ ] 任何视觉优化不得移除原按钮、字段、节点类型、数据项或快捷操作。

## 8. 实施约束

1. 先建立视觉基线和页面截图清单，再分模块改造。
2. 优先通过共享 CSS token 和基础组件实现一致性，避免在每个模块写独立样式。
3. 逐页重构时同步核对原有 DOM 事件、全局函数、模块注册、Store 字段与路由 ID。
4. 每次改造执行 18 页面路由冒烟、关键交互 E2E 和功能清单差异检查。
5. 不将纯 CSS 美化宣称为功能交付；视觉质量与功能正确性分开验收。
