## 一、用户角色定义

### 1.1 核心角色

```
角色 1: 平台管理员 (Platform Admin)
├─ 职责: 系统配置、权限管理、安全审计
├─ 操作频率: 低（偶发）
├─ 场景: 组织导入、权限配置、审计日志查看
└─ 技能: 中等（IT 背景）

角色 2: 组织管理员 (Tenant Admin)
├─ 职责: 组织架构、菜单配置、基础设置
├─ 操作频率: 低（初期高）
├─ 场景: 建立部门、配置菜单、创建应用
└─ 技能: 中等（业务负责人）

角色 3: 应用开发者 (App Developer)
├─ 职责: 创建应用、设计业务流程
├─ 操作频率: 高
├─ 场景: 一句话生成 → 编辑完善 → 发布
└─ 技能: 低-中（业务人员或 IT 人员）

角色 4: 业务管理员 (Business Admin)
├─ 职责: 配置权限、管理用户
├─ 操作频率: 中
├─ 场景: 分配权限、创建角色
└─ 技能: 中

角色 5: 终端用户 (End User)
├─ 职责: 使用应用提交数据
├─ 操作频率: 高
├─ 场景: 填表、审批、查看报表
└─ 技能: 低（无需 IT 知识）
```

## 二、典型业务场景

### 场景 A: 订单管理系统 (简单 CRUD 应用)

**目标用户：** 应用开发者（10 分钟快速创建）  
**涉及模块：** 应用管理 → 数据建模 → 表单设计 → 权限管理 → 部署

#### A.1 完整流程

```
Step 1: 应用创建 (AI 一句话生成) [2 min]
└─ 用户操作:
   ├─ 进入应用列表
   ├─ 点击 [创建应用] 按钮
   ├─ 选择 "AI 一句话生成"
   ├─ 输入: "给我做个订单管理系统"
   ├─ AI 多轮澄清:
   │  1️⃣ "这是什么行业的订单？"  → 用户: "电商"
   │  2️⃣ "预期用户数量？"        → 用户: "1000-10000"
   │  3️⃣ "需要哪些报表？"        → 用户: "日统计、收入分析"
   │  4️⃣ "审批流程复杂度？"      → 用户: "简单（3 级）"
   └─ AI 生成应用骨架
   
Step 2: 应用内容编辑 (精细化调整) [5 min]
└─ 用户操作:
   ├─ 进入应用编辑页
   ├─ 查看 AI 生成的建议
   │  ├─ 数据模型: 订单表、客户表、商品表（可编辑）
   │  ├─ 表单字段: 20+ 字段已生成（可增删）
   │  ├─ 工作流: 3 个环节（可调整）
   │  └─ 权限: 3 个角色（可增删）
   │
   ├─ 编辑数据模型:
   │  ├─ 进入 [数据建模设计器]
   │  ├─ 查看 ER 图
   │  ├─ 添加一个新字段 (备注)
   │  ├─ 调整字段验证规则
   │  └─ [保存] → 自动生成 Prisma Schema
   │
   ├─ 编辑表单:
   │  ├─ 进入 [表单设计器]
   │  ├─ 调整字段顺序
   │  ├─ 修改字段显示名称 (中英文)
   │  ├─ 添加字段验证提示
   │  └─ 预览表单
   │
   ├─ 编辑工作流:
   │  ├─ 进入 [BPM 流程设计器]
   │  ├─ 查看 3 个环节: 草稿 → 待审 → 已确认
   │  ├─ 调整审批人配置:
   │  │  ├─ 环节 2 审批人: "销售部主管" (组织架构动态配置)
   │  │  └─ 自动从组织架构查询
   │  └─ 添加回退权限
   │
   └─ 编辑权限:
      ├─ 进入 [权限管理]
      ├─ 查看 3 个角色: 销售员、销售主管、管理员
      ├─ 给销售员添加额外权限: [查看报表]
      └─ AI 权限推荐: "销售主管通常需要 [月度审计] 权限" (95% 置信)

Step 3: 数据初始化 [1 min]
└─ 用户操作:
   ├─ 导入客户数据 (Excel)
   ├─ 导入商品分类 (CSV)
   └─ 应用自动生成初始化脚本

Step 4: 应用发布 [1 min]
└─ 用户操作:
   ├─ 点击 [生成制品]
   ├─ 系统生成:
   │  ├─ Prisma Schema
   │  ├─ 种子数据
   │  ├─ 表单定义 JSON
   │  ├─ 工作流 BPMN XML
   │  ├─ 权限配置 JSON
   │  └─ 资源清单
   ├─ 点击 [发布]
   ├─ 选择目标环境: 测试 → 生产
   ├─ 灰度发布 (10% 流量)
   └─ 应用上线

总计时间: 9 分钟 ✅
```

#### A.2 终端用户使用流程

```
Step 1: 登录应用
└─ 用户在浏览器访问应用 URL
   ├─ 显示登录页 (自定义公司 Logo + 背景)
   ├─ 输入工号和密码
   └─ 验证成功 → 进入应用首页

Step 2: 创建订单
└─ 点击菜单 [订单管理] → [创建订单]
   ├─ 表单自动显示中文/英文标签 (根据用户语言偏好)
   ├─ 填写表单:
   │  ├─ 订单编号: 自动生成 (JD-2026-00001)
   │  ├─ 客户名称: 下拉选择（从导入的客户表）
   │  ├─ 商品: 多行编辑表格
   │  ├─ 总金额: 自动计算
   │  └─ 备注: 自由文本
   ├─ 表单验证:
   │  ├─ 客户名称为必填 (验证错误实时显示)
   │  ├─ 总金额格式检查
   │  └─ 金额 > 10000 时标记为 "需审批"
   └─ 点击 [提交]

Step 3: 工作流自动触发
└─ 后端逻辑编排执行:
   ├─ 条件判断: IF 金额 > 10000 THEN 需审批
   ├─ 若需审批:
   │  ├─ 查询销售部主管 (从组织架构)
   │  ├─ 发送审批通知 (邮件/站内信)
   │  └─ 订单状态: 待审批
   └─ 若无需审批:
      └─ 订单自动确认

Step 4: 审批人处理
└─ 审批人收到通知
   ├─ 进入 [审批中心]
   ├─ 查看待审批订单列表
   ├─ 点击订单查看详情
   ├─ 执行审批动作:
   │  ├─ [同意] → 订单确认
   │  ├─ [拒绝] + 拒绝原因
   │  ├─ [转发] 给其他主管
   │  └─ [委托] 给代理人
   └─ 完成审批

Step 5: 查看报表
└─ 任何人都可进入 [报表]
   ├─ 预置的 3 个报表:
   │  ├─ 日统计: 今日订单数、总金额、平均订单额
   │  ├─ 收入分析: 周/月/年收入趋势图
   │  └─ 客户分析: 客户 LTV 排名
   │
   ├─ 报表可交互:
   │  ├─ 日期范围筛选
   │  ├─ 客户/销售员筛选
   │  └─ 导出为 PDF/Excel
   │
   └─ AI 数据洞察:
      ├─ "与上月相比增长 23%"
      ├─ "Top 10 客户贡献 45% 收入"
      └─ "平均订单周期 7.2 天"
```

### 场景 B: 复杂审批流程 (工作流应用)

**目标用户：** 应用开发者（流程设计师）  
**涉及模块：** BPM 设计器 → 逻辑编排 → 组织架构 → 权限管理

#### B.1 流程概述

```
原始需求: 请假审批流程（3 级审批，支持委托/抄送/回退）

流程结构:
申请人提交请假单
  ↓
AI 自动推荐工作流模板
  ↓
编辑流程:
  ├─ 环节 1: 直属主管审批
  │  ├─ 参与者: "员工的直属主管" (从组织架构)
  │  ├─ 权限: 审批、拒绝、转发、委托、抄送
  │  └─ 超期提醒: 3 天
  │
  ├─ 环节 2: 部门经理审批
  │  ├─ 参与者: "部门主管" (从组织架构)
  │  ├─ 条件: 请假天数 > 3 天
  │  └─ 若 ≤3 天，直接跳转环节 3
  │
  ├─ 环节 3: HR 审核
  │  ├─ 参与者: HR 角色
  │  ├─ 权限: 只审查，不能拒绝
  │  └─ 超期提醒: 1 天
  │
  └─ 完成
     ├─ 发送确认邮件给申请人
     ├─ 记录审批历史
     └─ 更新员工假期余额
```

#### B.2 逻辑编排详解

```
使用【模块 5 逻辑编排设计器】:

流程图:
┌─ 事件: 表单提交
│
├─ 条件判断 1: 请假天数 > 3 ?
│  │
│  ├─ TRUE → 环节 1,2,3 顺序执行
│  │          └─ 数据操作: 获取部门主管 ID (SQL Query)
│  │          └─ API 调用: 发送通知
│  │
│  └─ FALSE → 跳过环节 2
│             └─ 环节 1 → 环节 3
│
├─ 循环: FOR EACH 审批人
│  └─ 发送邮件通知
│
├─ API 调用: 更新员工请假余额
│  ├─ URL: PUT /api/employees/{id}/leave-balance
│  ├─ Body: { daysTaken: 2, reason: "Annual Leave" }
│  └─ 错误处理: IF response.status != 200 THEN 告警
│
└─ 返回: { status: "approved", ...}

代码生成 (TypeScript):

export async function handleLeaveApproval(leaveRequest: LeaveRequest) {
  const { approverId, employeeId, days } = leaveRequest;
  
  // 1. 条件判断
  if (days > 3) {
    // 获取部门主管
    const deptManager = await db.employee.findMany({
      where: { 
        department: { ... },
        position: { level: 'M2' }
      }
    });
    
    // 通知直属主管 → 部门主管 → HR
    await notifyApprovers([approverId, deptManager.id]);
  } else {
    // 直接 HR 审核
    await notifyApprovers([hrTeamId]);
  }
  
  // 2. 循环发送通知
  for (const approver of approvers) {
    await sendEmailNotification({
      to: approver.email,
      subject: `请假申请审批 - ${employeeId}`,
      message: `${employeeId} 申请请假 ${days} 天`
    });
  }
  
  // 3. API 调用
  try {
    const response = await axios.put(
      `/api/employees/${employeeId}/leave-balance`,
      { daysTaken: days, reason: "Annual Leave" }
    );
  } catch (error) {
    console.error('Failed to update leave balance:', error);
    // 告警通知管理员
  }
  
  return { status: 'approved' };
}
```
