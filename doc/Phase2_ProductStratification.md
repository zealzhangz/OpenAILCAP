# OpenAILCAP 第 2 步：产品分层设计（需求阶段）

## 2.1 明确三条产品线（基于复杂度分层）

### 产品线 A：AI 完全自动化（表单 / CRUD 类应用）

**目标用户：** 非技术业务人员、小型企业 IT

**使用场景：**
```
"给我做个订单管理系统"
"我需要一个客户关系管理系统"
"帮我做个库存管理"
"创建一个报价单系统"
```

**AI 能力：**
```
输入：一句话需求 (10-50 字)
   ↓
智能问卷澄清 (3-5 个问题)
   ↓
一键生成：
  ✓ 数据模型（字段、类型、验证规则）
  ✓ 表单设计（布局、权限、联动）
  ✓ 列表视图（排序、筛选、导出）
  ✓ 权限配置（角色、字段级权限）
  ✓ 基础工作流（创建→审核→完成）
  ✓ 部署配置（本地 or 云端）
```

**技术复杂度：** ⭐⭐ (低)

**AI 生成流程：**
```
步骤 1：需求理解
  用户描述 → NLU 提取实体 → 识别应用类型
  例：
    "订单管理" → 类型: Sales Order
    字段数量：20-30 个
    并发用户：50-200 个
    审批环节：1-3 个

步骤 2：澄清式对话
  系统自动弹出问卷：
  [ ] 这是什么行业？电商/B2B/制造/其他
  [ ] 需要多少个用户？<100/<1000/>1000
  [ ] 需要财务报表吗？是/否
  [ ] 是否需要库存管理？是/否

步骤 3：生成计划书
  基于回答生成：
  ✓ 预计 20 个字段示例
  ✓ 预计 2 个工作流步骤
  ✓ 预计 3 个用户角色
  "确认此计划，开始生成?" [确认] [修改]

步骤 4：自动生成
  AI 生成代码 → 自动单测 → 自动部署
  预期时间：3-5 分钟（从需求到可用系统）

步骤 5：用户验证
  "生成成功！请查看系统，有问题点此修改"
  用户点"修改"可进入手工编辑或再次 AI 优化
```

**目标 KPI：**
```
✓ 生成成功率 ≥ 90% (用户无需修改或修改 <5%)
✓ 用户满意度 ≥ 85% (NPS > 50)
✓ 重复使用率 ≥ 60% (用户再次使用的比例)
✓ 生成平均时间 < 5 分钟
```

 其他：无折扣"

↓ AI 代码生成

// 生成的 TypeScript 代码
interface Customer {
  id: string;
  level: 'VIP' | 'Standard';
}

interface Order {
  customerId: string;
  amount: number;
}

async function calculateDiscount(
  order: Order,
  customer: Customer
): Promise<number> {
  try {
    // 输入验证
    if (!order || !customer || order.amount < 0) {
      throw new Error('Invalid input parameters');
    }

    // 业务逻辑
    if (customer.level === 'VIP' && order.amount > 1000) {
      return 0.15;
    }
    if (customer.level === 'Standard' && order.amount > 500) {
      return 0.05;
    }
    return 0;
  } catch (error) {
    console.error('Error calculating discount:', error);
    throw error;
  }
}

export { calculateDiscount };
