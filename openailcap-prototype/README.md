# OpenAILCAP MVP 2.1 — 交互式原型

> **交付边界（重要）：** 本目录当前是交互式 UI 原型，不是生产平台后端，也不是 GB/T 46900—2025 引领级符合性证明。原型使用 Node.js 内置 HTTP 静态服务器和浏览器 localStorage；没有 NestJS 业务 API、PostgreSQL/Prisma 服务或真实 LLM/Agent 服务。界面中的演示数据、模拟执行和本地规则模板必须与生产实现区分。

## 本轮整改

- 统一工程工作台视觉系统，保留既有导航、模块脚本和页面入口。
- 引入 Anthropic `frontend-design` Skill：`.agents/skills/frontend-design/`。
- AI 应用生成向导已修复步骤状态，生成的 AppSpec、模型、表单、逻辑和可选 BPM 流程草稿会写入原型状态。
- LogicFlow 增加基于当前图的连线增删、可达性模拟、图定义导出和规则模板生成。
- BPMN 增加基于当前节点/连线的 XML 导入导出、连线编辑、图仿真和发布前结构校验。
- 表单设计器增加本地撤销/重做、保存修订、布局切换和可选 AI 字段建议。
- 数据建模 AI 建议可在用户确认后写入实体/关系集合；DDL 预览根据当前模型生成。
- 以上功能仍属于浏览器原型行为；未连接真实后端、数据库、流程引擎或 LLM。

## 启动

要求 Node.js 18 或更高版本，无需安装第三方依赖。

```bash
cd openailcap-prototype
node server.js
```

浏览器访问 http://localhost:3000。

## 检查

```bash
npm test
```

静态测试会检查所有前端 JavaScript 语法、入口资源、增强脚本加载顺序和功能保留基线。它不替代浏览器 E2E、真实数据库集成、安全测试或国标评估。

## 当前限制

1. 数据存储仍为浏览器 localStorage，仅用于单浏览器演示；不具备多用户、租户隔离、并发一致性或服务端备份能力。
2. AI 应用/建模/逻辑生成目前使用本地规则模板，不代表真实模型调用或 Agent 编排。
3. LogicFlow/BPMN 仿真用于图结构验证，不执行真实业务副作用；BPMN XML 仍需使用 BPMN 2.0 XSD 和真实流程引擎验证。
4. Prisma/DDL 生成预览尚未连接临时 PostgreSQL 和 Prisma CLI；不得用于生产迁移。
5. 密钥、国密、安全、设备、插件、应用市场、跨平台能力不能因存在演示界面而标记为实现完成。
6. 当前测试为静态/语法测试；需要补充 Playwright E2E、API/DB 集成、安全、性能和恢复演练。

## 交付目标

项目目标是 GB/T 46900—2025 第 7 章引领级：九个能力域全部适用 L1/L2/L3 要求。详细设计、功能保留和证据状态以仓库 `doc/整改/` 为准。没有实现、测试和独立复核证据的条款一律不计入交付完成率。
